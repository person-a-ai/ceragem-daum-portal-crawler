# 세라젬 Daum 포털 텍스트 크롤러

다음 포털 내 5대 텍스트 수집 경로를 상호 배타적이고 완전하게 분할하여 수집하는 고성능 멀티배치 크롤러입니다.

---

## 1. 수집 대상 및 아키텍처

다음 검색 포털의 전체 텍스트 수집 영역을 번호로 선택하여 수집할 수 있습니다.

| 번호 | 수집 대상 | 검색 파라미터 | 특징 및 지원 내용 |
|---|---|---|---|
| **0** | 다음카페 | `w=fusion&col=cafe` | 카페 메인 iframe 내부 본문 및 댓글 추출 |
| **1** | 다음블로그 (티스토리) | `w=fusion&col=tistory` | 티스토리 게시글 본문 및 메타데이터 추출 |
| **2** | 다음블로그 (브런치) | `w=fusion&col=brunch` | 브런치스토리 본문 및 메타데이터 추출 |
| **3** | 다음웹문서 | `w=fusion&col=web` | 웹문서 본문 및 메타데이터 추출 |
| **4** | 다음뉴스 | `w=news` | 다음 뉴스 기사 본문 및 메타데이터 추출 |

* **수집 기간**: HTTP 버전은 `START_DATE`\~`END_DATE`(기본 `20240101`\~`20260630`)를 월별 구간으로 나눠 최신 월부터 관련도순으로 탐색합니다. 키워드당 상한(`TARGET_COUNT`)은 비워 두면 월 수 x 150개로 자동 계산됩니다. (다음 검색은 한 구간당 최대 150개까지만 보여줌)
* **다중배치 성능**: `MAX_WORKERS`(기본 8)개 워커 병렬 수집
* **에러 제어**: HTTP 버전은 개별 글/댓글 수집 실패를 `수집_경고.txt`에 기록하고 계속 진행하며, 네트워크가 끊기면 연결이 복구될 때까지 대기한 뒤 이어서 수집합니다. 검색 요청이 재시도 후에도 실패하거나 '결과 없음' 안내 없는 빈 응답이 오면(차단 의심) 그 키워드는 저장하지 않고 넘어가며, 재실행 시 다시 수집합니다.

## 3. 크롤러 버전별 특징

### A. HTTP 직접 요청 버전
* 브라우저 창 띄움 및 탭 생성 오버헤드가 없어 셀레니움 대비 30배 이상 빠릅니다.
* macOS 가상 데스크톱 화면 전환이나 포커스 뺏김 현상이 일절 발생하지 않습니다.
* 서버가 닫혔거나 글이 삭제된 오류 링크를 네트워크 수준에서 즉시 감지하여 유효한 글만 깔끔하게 저장합니다.
* 브런치(API)·티스토리(모바일 API) 댓글 원문을 답글까지 수집합니다. (비밀댓글 제외)
* 네트워크가 끊기면(노트북 덮개 닫힘 등) 자동으로 일시 정지했다가 연결이 복구되면 재개합니다.
* 이어하기: `data_csv/`에 이미 저장된 키워드 파일은 건너뜁니다. 결과가 0개인 파일은 검증 기록(`_verified_zero.tsv`)이 있는 경우만 완료로 처리하고, 아니면 재수집합니다.
* **글 캐시(SQLite)**: 같은 URL은 한 번만 요청하고 이전 수집 결과를 복사합니다. 받은 글과 삭제된 글(404/410)을 노트북 폴더의 `post_cache.sqlite`에 저장해 메모리를 쓰지 않고, 재시작해도 그대로 이어서 씁니다. `data_csv/`의 CSV 중 아직 반영하지 않은 파일만 캐시에 넣습니다(처음 한 번은 전체 CSV를 읽어 오래 걸릴 수 있음). 캐시 파일은 지워도 CSV로 다시 만들어지며, 지울 때는 `-wal`, `-shm` 파일도 함께 지우세요.
* **안전한 저장**: CSV를 `.tmp`에 다 쓴 뒤 바꿔치기해서, 쓰는 도중 멈춰도 반쯤 쓴 파일이 완료로 남지 않습니다.
* **Interrupt 즉시 중단**: ■(Interrupt)를 누르면 남은 작업을 취소하고 진행 중인 키워드도 몇 초 안에 멈춥니다(중간에 멈춘 키워드는 저장 안 함). 4-2(이어하기·캐시) 셀부터 다시 실행하면 이어서 수집합니다.
* 검색 결과가 한 페이지(15개)에 못 미치면 마지막 페이지로 보고 다음 페이지 요청을 생략합니다.
* 본문 길이 제한(`MAX_CONTENT_CHARS`)은 기본 꺼짐(None)입니다.

### B. 셀레니움 브라우저 버전
* 실제 구글 크롬 브라우저를 기반으로 동작합니다.
* `USE_HEADLESS = True` 설정이 기본 적용되어 브라우저 창이 백그라운드에서 조용히 실행됩니다.
* 만료/에러 페이지 접속 시 크롬 자체 오류 안내문 화면을 스킵하도록 예외 필터가 적용되어 있습니다.
* 상단 통합 설정 셀에서 수집 기간(`START_DATE`\~`END_DATE`), 키워드당 상한(`TARGET_COUNT`, 기본 3,000), 워커 수(`MAX_WORKERS`, 기본 4), 수집 대상, 키워드를 한곳에서 지정합니다.
* 수집 기간은 월별 구간으로 자동 분할해 최신 월부터 관련도순으로 수집합니다.
* 이어하기(`RESUME_FROM_SAVED = True`): `data_csv/`에 이미 저장된 키워드 파일은 건너뜁니다.

## 4. 실행 단계별 가이드

1. **설정값 지정**
   * `SELECTED_TARGETS = [0, 1, 2]` 리스트에 원하는 수집 대상 번호를 입력합니다.
   * `main_keywords`와 `invest_key`에 원하는 검색 키워드를 입력합니다.
   * 셀레니움 버전의 경우 `USE_HEADLESS` 옵션으로 창 숨김 여부를 제어할 수 있습니다.

2. **중복 제외 CSV 확인**
   * 이미 수집된 파일과 겹치지 않게 하려면 기존 CSV 파일을 각 폴더 내 `overlap_data/` 디렉토리에 넣어둡니다.
   * 코드가 자동으로 고유 URL을 추출하여 수집 대상에서 사전 제외합니다.

3. **크롤링 실행**
   * 제자리 고정 진행률 표시줄이 실행되며, 줄 도배 없이 현재 수집 성공 건수와 실패 건수가 실시간으로 갱신됩니다.
   * 예시: `[다음카페 | 귀농 +%2B건강식 ] 현재 수집: 10개, 실패: 2개`

4. **전체 데이터 통합 병합**
   * 기본적으로 전체 줄이 주석 처리되어 있습니다.
   * 수집 완료 후 6번 셀 전체 선택 후 `Cmd + /` 키를 눌러 주석을 해제하고 실행하면, `data_csv/` 내 모든 개별 파일이 하나의 통합 CSV로 자동 병합됩니다.

## 5. 최종 CSV 데이터 스키마

생성되는 모든 CSV 파일은 원본 네이버 크롤러와 100% 동일한 9개 컬럼 규격 및 엑셀 호환 인코딩을 준수합니다.

| 컬럼명 | 설명 | 비고 |
|---|---|---|
| `date` | 작성일시 | 메타 태그 및 화면 날짜 정규화 |
| `keyword` | 검색 키워드 | 메인 키워드 및 상세 키워드 조합 |
| `title` | 게시글 제목 | 본문 제목 텍스트 |
| `contents` | 게시글 본문 | 불필요한 공백 및 유니코드 제거 |
| `comments` | 댓글 목록 | 리스트 형태 텍스트 |
| `site` | 수집 출처 | 다음카페, 다음블로그_티스토리 등 |
| `url` | 원본 게시글 URL | 정규화된 고유 URL |
| `author_nickname` | 작성자 닉네임 | 미기재 시 '닉네임 없음' |
| `comment_nicknames` | 댓글 작성자 닉네임 목록 | 미기재 시 '댓글 닉네임 없음' |

* **인코딩**: `utf-8-sig`
* **인덱스**: 미포함
* **중복 제거**: 저장 직전 정규화 URL 기준 중복 행 자동 제거
